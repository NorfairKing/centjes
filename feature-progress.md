### Research findings

- Existing importers (`centjes-import-{neon,revolut,cornercard}`) are all one
  module plus an OptParse module, no test suite at all. They read one CSV with
  cassava `decodeByName`, load the ledger for currencies via
  `loadModules` + `compileDeclarationsCurrencies`, build `Declaration ()`
  values, and write `formatModule` output to a file.
- `centjes-stripe` is the model for a *testable* importer: pure
  `Centjes.Stripe.Declarations` with a `DeclarationSettings` record, and a test
  suite with `goldenTextFile`, re-parse round trips, and
  `settingsLintSpec`/`goldenSettingsReferenceDocumentationSpec`.
- `~/src/finance/banks/wise.cent` (hand-maintained) is the target shape:
  one multi-currency `assets:wise` account, conversions as a single transaction
  with `@ num / den CUR` exact price plus a fee posting and balance assertions,
  fees to `expenses:banking:wise` tagged `tax-deductible`/`not-vat-deductible`.
- Price annotation type: `PriceAnnotationCost (CostExpression
  (RationalExpression numerator (Just denominator) False) currency)`.
- Wiring points for a new package: `nix/overlay.nix` (`centjesPackages`),
  `flake.nix` (coverage-report list), docs site (`routes`, a Handler module,
  `content/pages/*.markdown`, `package.yaml` dependency), `CLAUDE.md`.
  `.cabal` and `default.nix` are generated by the hpack/cabal2nix hooks.

### Decisions (answered by the user)

- Conversions: pair legs across several statement CSVs in one run, emit one
  transaction with both currency postings and an exact price.
- Input format: the per-balance "Statement (CSV)" export.

### Approved plan

See the plan in the conversation; summarised:

- New package `centjes-import-wise` with modules `Statement` (Row parsing),
  `Pair` (conversion pairing), `Declarations` (pure transaction building),
  `Wise` (IO glue), `OptParse`.
- Settings: `--ledger`, one or more `CSV_FILE` arguments, `--output`,
  `--assets-account` (`assets:wise`), `--expenses-account`, `--income-account`,
  `--fees-account` (`expenses:banking:wise`), `--fee-tag` (repeatable).
- Unpaired conversion legs are a hard error, not a silent half-import.
- Tests: `StatementSpec`, `PairSpec`, `DeclarationsSpec` (golden `.cent`,
  postings sum to zero, assertions match running totals, re-parse round trip),
  `OptParseSpec` (lint + documentation golden).
